# STORY-FLAGS — story-data issues (engine does not rewrite story content)

Generated by `scripts/story-flags.ts` (28p). Each line is a sentence in authored story data that reads as an author/writer note. Since 28p the engine drops these at the story-data boundary (`storyDataBoundary.ts`) before they reach facts, speech, page 1, cards, or item text. The authored files still hold them; an author should rewrite them as in-world text or move them into `premise` / `styleRail` (writer rails). "No hub bank" means the story ships no place list, so the engine derives place cards from its own hook locations and world lore.

## Not auto-stripped (needs an author)
- Thornferry Road `hookDeck[6].page1` (magistrate's porch) opens with "You start on the magistrate's porch, not the mill." — stage direction inside player-facing page 1. Stage-direction shapes are only stripped from telegram fields, so page 1 keeps it.
- Thornferry Road hook locations carry time/clause tails ("Thornferry mill at last light", "the mill loft before Wren finds you"). The engine trims them for place-card names; the label is still the `currentLocation` string players see.
- Thornferry Road `keyNPCs` (Wren Holt "Will walk with the player or against them.") and `loreSnippets` ("The player does not start there.", "If the player accepts Wren, describe…") lose those sentences in play; the design intent now lives only in `premise`.
- Thornferry Road hook-card `text` fields that survive the filter are still sibling-comparison notes ("Wren's question is sharper. The charter is heavier."). Since 28p card `text` is not used when a card has `page1`.
