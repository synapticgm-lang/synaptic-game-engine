# SynapticGM Comic / Graphic Novel Mode Maximizer — Requirements Matrix

## Fixed product laws

1. Live image generation produces scene art only. Dialogue, captions, sound effects, logos, and UI stay in HTML/SVG overlays. Baking is allowed only for after-the-fact PDF/export.
2. The player art path is hosted OpenRouter through the existing edge `generate-image` route. Free, Mid, and High cannot require player BYOK.
3. Kid Mode rewrites or skips before any image-generation spend. Core Kid Mode story visuals cannot require advertising.
4. Style language must be original and technique-based. Licensed comics, manga titles, franchise names, living artists, scraped assets, and imitation prompts are prohibited.
5. Text and the story ledger are canonical. Art cannot invent roster members, props, locations, outcomes, wounds, or facts, and an art failure cannot block play.
6. Existing overlay lettering is a settled decision and is not reopened.
7. Scope is the live SynapticGM consumer game only. No World of Fantasy scope, content, races, places, or multiplayer.
8. No production TypeScript, code patches, PRs, second critic/Continuity-Warden LLM, Artistly-like SaaS production integration, or pirate asset packs.

## Required package shape

The final deliverable is one Markdown package beginning with a ten-line executive and containing sections A–H exactly:

- **A:** Industry-technique gap analysis with a table and verdict.
- **B:** End-to-end player and system pipeline with source precedence, Director decision, and Classic/Memorable reuse.
- **C:** Ranked character-consistency techniques plus Free/Mid/High stacks.
- **D:** Original 2-, 3-, 4-, and 6-panel pointer-card banks, including reading order, camera, overlay zones, use, and exclusions.
- **E:** Concrete tier cost model including retry economics, skip rules, caps, frequency defaults, and Classic/Memorable comparison.
- **F:** At least 20 engineering fixtures: at least 10 good and at least 10 must-reject, each with setup, hard outcome, and module owner.
- **G:** Existing-module-oriented P0/P1/P2 build board with files, dependencies, risks, kill criteria, done-when metrics, and explicit near-term No-Go list.
- **H:** Six first-class alternative techniques scored for impact, cost, continuity fit, and latency, with Free and upgrade recommendations.

The package ends with no more than eight open founder decisions and a numbered reference list.

## Confirmed parallel research workstreams

The phase-2 input list is complete and intentionally homogeneous: each workstream must return public technique shapes, practical effects, cost/latency implications, consistency risks, transferable techniques, prohibited copying, and primary-source URLs.

1. **Vertical-scroll and webtoon creator workflows:** public docs and UX patterns for vertical reading, gutters, reusable assets, shot sequencing, and publishing layout.
2. **Layout-first AI comic creator workflows:** ComicAI-, AI Comic Factory-, and Anifusion-class public flows covering script ingestion, character setup, panel layout, generation, regeneration, and lettering separation.
3. **Midjourney reference workflows:** official character-reference, omni-reference, style-reference, seed, and prompt-weight behavior relevant to identity and visual consistency, without using protected style targets.
4. **Storyboard and script-to-panel workflows:** Storyboarder.ai-class public flows plus adjacent storyboard systems covering beat selection, shot lists, camera choices, and deterministic panel planning.
5. **Academic panel layout and reading-order research:** open papers and datasets addressing panel segmentation, reading order, closure, page composition, and narrative sequencing.
6. **Visual-novel and virtual-tabletop layering analogues:** public documentation for layered portraits, backgrounds, overlays, tokens, scene states, and other low-cost comic effects that preserve text as truth.

## Source hierarchy and evidence rules

Official product documentation, official help centers, original papers, publisher pages, and author/project pages are preferred. Search snippets are not evidence. Secondary articles may supply context only when primary material is unavailable. Public workflows may be studied, but private code, scraped assets, and reverse-engineered implementation details are outside scope.

## Decisions to resolve from evidence

- Keep Director hard-disabled for P0, allow an optional Mid/High planner later, or replace it with deterministic code templates.
- Define when accepted GM `<panel>` tags are authoritative versus when deterministic BeatSpec/layout templates supply the panel plan.
- Establish realistic Klein/Flux support for seed control, image conditioning, reference reuse, and premium variants through the hosted route.
- Select the minimum viable P0: Memorable-only comic chrome, one eligible event plate, or comic-lite one-panel-plus-overlay.
- Set tier envelopes and frequency defaults using formulas and explicit planning assumptions rather than invented vendor prices.
- Define hard kill criteria that protect latency, spend, Kid safety, ledger truth, and Classic/Memorable users.

## Validation checklist

The final pass must verify all A–H sections exist, the executive is exactly ten lines, every externally grounded factual claim has an inline numeric citation, every reference is public, all 20+ fixtures identify a module owner, every layout card uses only the existing five anchor values, P0 is shippable this month, and none of the hard bans are violated.
