# SynapticGM Game Vibe — Research and Implementation Omnibus

This package is a fresh-research implementation specification for making SynapticGM feel fluid, consequential, personal, and genre-true without compromising the authoritative ledger.

1. **`00_executive_vibe_scorecard.md`** gives the product decision, launch gates, and design scorecard.
2. **`V1_vibe_constitution_and_matrix.md`** defines the non-negotiable feel laws.
3. **`V10_build_backlog_and_anti_list.md`** is the recommended implementation sequence.
4. **`V11_research_complete_checklist.md`** identifies code-ready work and required validation/counsel gates.

## Non-negotiable implementation invariant

```text
player correction → pinned canon → StateTx → SceneManifest → evidence → invention
```

A retrieval result, RAG output, generated summary, personality profile, theme, TTS layer, ambient line, or visual splash **cannot create or override ledger truth**. The package consistently labels unverified design recommendations as **SPECULATIVE** and external/public-policy review items as **COUNSEL**.

## Suggested implementation order

Build the P0 correctness surface first: correction transaction, semantic/style firewall, material receipts, OpenAsk Q&A, and continuity fixtures. Only then layer personality selection, HookArc variation, visual splash, and audio-lite cosmetic features. This order ensures that “it remembered” and “it answered me” are earned in play rather than advertised as abstract model capabilities.
