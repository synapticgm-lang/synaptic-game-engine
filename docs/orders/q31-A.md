# q31-A: SRD monster names in the combat log

Order A from `docs/orders/queued-fix-orders.md`. Stamp `2026-10-15j`. Player-facing play change (the STATUS combat log), so the stamp moves. Client only: `roundFight.ts` has no edge copy, so gm-turn was not deployed.

## Cause

`src/game/tabletop/roundFight.ts:208` (at `e2a826a7`), `foeIdentity.statusName`:

```ts
const statusName = (i: number) => (count === 1 ? enc.name : `${block.srd ? block.name : enc.name} ${i + 1}`);
```

`statusName` is the name every `RoundFoeState` carries. Every `who:` / `target` in `rules/roundCombat.ts` reads `foe.name`, and so does the single-foe initiative line at `roundCombat.ts:226`. With one foe it was the road label (`FOE_NAME.undead = 'the restless dead'`). The order traced this to `roundCombat.ts:226`, but that line only echoes `f.name`. The name is chosen once, in `foeIdentity`.

Since tt-fix-2 (the SRD encounter budget), the ds151 tape meets one zombie, not three. That headcount is correct SRD 5.2.1. The bug was the log name.

## Fix

The fix is in one place, where the foe is named (`foeIdentity`), so there is no per-`who:` helper:

```ts
const logged = block.srd ? block.name : enc.name;
const statusName = (i: number) => (count === 1 ? logged : `${logged} ${i + 1}`);
```

- A lone SRD foe is logged as `Zombie`. Several are `Zombie 1`, `Zombie 2`, and so on.
- A non-SRD (engine) block keeps the encounter name.
- `writerName` and the `relabel` map are unchanged, so the writer-facing fact still says "the restless dead".
- An old save with a fight already running keeps its stored foe names for that fight (`resumeCombat`).
