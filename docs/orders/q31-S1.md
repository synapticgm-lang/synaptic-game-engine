Tag `q31-S1`. Play change: it bumps the stamp and deploys the client. Edge copies changed (`intentParser`, `types`, `universalHardRails`), so gm-turn is redeployed.

## Cause (traced)

The rule was enforced on the **words going in**, not on the **death coming out**.

- `src/game/inputMediation.ts:25-26, 113-137` (at `16bd4e76`): one regex (`GAME_PERM_SELF_KILL`) on the typed text blocked some wordings. Paraphrases ("I turn my sword on myself", "let it take me", "open my wrists") passed; chips never reached it; `ctx.hasRevivePath` was never passed by either caller.
- Death was written in four places with no cause: `tabletop/roundFight.ts:514-529` (defeat, through `cheatDeath` :581-605), the death-save path :623-636, and `travelJourney.ts:1511` (`exhaust`, used by the forced march :1557 and starvation :1721), which wrote `dead: true` directly and skipped the table's `deathRule`.
- Nothing knew a death was self-inflicted, so nothing could stop it where it happens.

## Fix (one shared mechanism)

1. **One death point.** `commitDeath(state, cause, rng, deathFact)` in the new `src/game/rules/death.ts`, `cause: 'danger' | 'self'`. Fight defeat, the death save, forced-march and starvation exhaustion all call it. `cheatDeath` / `endAttunementOnDeath` / Revivify moved into its `danger` branch (no copy left behind), so **road deaths now respect `deathRule`** (mercy wakes at 1 HP). A grep test fails if `dead: true` is written anywhere else under `src/game` or `_shared/gm`.
2. **`cause === 'self'` never leaves the PC dead, in any mode or setting, with no coin or XP cost:**
   - LitRPG: the character's `lifeline` trait (System lifeline): STATUS `Lifeline: engaged — self-termination denied. HP set to 1.`
   - Story RPG: the fate charm on `lifeline` (default "an old oath that will not let you go"): `Lifeline: … — you live, at 1 HP`.
   - Tabletop (and any mode without a trait): knocked out, waking an hour later at 1 HP: `Death rule (self): knocked out — …`. Recorded in `docs/design/mode-rules-matrix.md` as a deliberate exception to SRD-as-written (John 11:38); normal danger deaths stay SRD.
   - The trait is created with the character (`defaults.ts` via `lifelineFor(mode)`; old saves fall back to the same function). `character.lifeline` added to `types.ts`.
3. **Where the cause comes from.** `parsePlayerIntent` (`intentParser.ts`) gets `targetsSelf`, read by one shared `aimsAtSelf(text)`: a harm verb whose object is the actor (any person), a lethal force let take the actor, or an act done so it all ends. Care acts ("cast Cure Wounds on myself", "steady myself", "cut myself free") are not self-aimed. `resolveEngineFight` (the shared engine entry the arc director runs for live play and Fate) settles a `targetsSelf` act through `commitDeath('self')` before anything else, so chips and typed text take the same path.
4. **The method is a Line, the moment a Veil.** The engine fact header tells the writer to fade and describe no method, wound, tool or death; the fact itself has no method words ("You stopped short…").
5. **`selfHarmMethod` token-gate class.** The same `aimsAtSelf` reading, run on the writer's lines: `classifyTokenLine` fails such a line with reason `selfHarmMethod` (dropped and repaired as usual) and `plainLineFactProblem` rejects it in the repair reply. No new checker.
6. `inputMediation` is now the real-person layer only (the crisis block stays unchanged). The word list, the `permanent_self_kill` block and the never-passed `hasRevivePath` (+ its three regexes in `universalHardRails`, src + edge) are deleted. Writer rail 3 (`universalHardRails.ts:15`, + edge mirror) now states the engine rule as a backstop.
7. `formatArcStatusReceipts` (`arcDirector.ts`) shows `Lifeline:` lines on STATUS (one alternative added to the existing receipt family; tabletop already shows `Death rule (`).

Every deletion is in `docs/orders/tt-cut-log.md`.
