# q31-K2: the engine settles commitments (Order K part 2)

Tag `q31-K2`. Stamp `2026-10-16z2`. Play change: a kept, broken, or expired commitment writes a STATUS line and moves trust. Edge `campaignMemory.ts` changed, so `gm-turn` is redeployed.

Tabletop and shared paths only. PYOA is skipped (no check while `engineMode` is `pyoa`).

## Cause

`recordTurnCommitments` (`src/game/stateTx.ts`, the return after recording, formerly ~526) stored an open commitment and never set kept, broken, impossible, or expired. `extractPromisesFromProse` (`campaignMemory.ts:146`, `PROMISE_PATTERNS`) was still the prose path into memory. Nothing read the turn record to settle a commitment.

## Fix

The same `recordTurnCommitments` pass, which `commitTurnRecord` already runs on both play paths, now settles open commitments. It runs every 3rd turn, and on any turn whose record has quest complete or fail, combat, an item change, or travel. A completed quest is kept. A failed quest is broken. A missing quest or deal is impossible. A passed `dueTurn` is expired. An inactive deal is broken. Trust moves through `shiftStoredRelationship` (+5 kept, −8 broken or expired). Impossible moves no trust.

`commitTurnRecord` adds the STATUS line: `Promise kept: You have fulfilled your promise to Joe Bloggs.` The same shape is used for broken, expired, Deal, and Agreement. One `systemNotice` rule formats all three for LitRPG (`Promise kept — …`). Tabletop shows the plain line. Writer prose is not read.

`extractPromisesFromProse` and `PROMISE_PATTERNS` are deleted (client and edge). Logged in `docs/orders/tt-cut-log.md`.
