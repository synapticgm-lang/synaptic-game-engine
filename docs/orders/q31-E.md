# q31-E: levelling per mode on one XP engine, with L3 as E.3

Order: `queued-fix-orders.md` Order E, with lap L3 merged in as E.3. Stamp **2026-10-15z** (client only; `gm-turn` unchanged because none of the changed files has an edge copy).

## Cause

- **E.1/E.2:** `src/game/xpRules.ts:260-298` (at `4be630c5`). `milestoneXp` chose each multiplier with its own `mode === 'dnd'` / `mode !== 'dnd'` check.
  - The difficulty scale (:264) and the over-level cut (:279) had no mode check, so tabletop paid Hard ×1.25 and the 5% cut. Its maths line showed `× 1.25 (Hard)` and `× 5% (level … vs area …)`.
  - `milestoneXpBase` (:298) sent every mode that was not `dnd` to the LitRPG table, so PYOA paid XP and levelled.
- **E.3 (L3):** `src/game/rules/srdMonsters.ts:137-154`. When a foe had no card CR and its name matched no SRD block, the engine used two different rules for it:
  - `statBlockForEncounter` fought it at the guessed `DND_DEFAULT_CR` (1/4).
  - `realEncounterCr` returned null, so the payout said `XP: none`.
  - The distill-1 tapes show this for engine-made dungeon foes ("Watchtower Stair Guard", "Blind Crawler"), which `dungeonCard.spawnFoe` (`dungeonCard.ts:589`) builds with no `cr`. The bible's own road foes (Road Bandit, Fog-Bank Cutter) already matched the SRD Bandit block.

## Fix (one shared mechanism each, no exception lists)

1. `xpRules.ts` `MODE_XP` is one row per mode: `{ xp, difficulty, overLevel, lowFoe, table }`. `milestoneXp` reads that row in place of the scattered mode checks.
   - Tabletop: every multiplier is 1, and the maths line is only `CR x = n XP ÷ party`. Difficulty still changes checks and to-hit.
   - LitRPG and Story RPG keep ×1.25 on Hard, the 5% over-level cut and the 25% low-foe share.
   - PYOA: `xp: false`, so it pays 0. `applyCharacterXpGain` (`characterXp.ts`) reads the same row, so PYOA never levels and gets no STATUS line.
2. E.3: `realEncounterCr` is now the one CR a foe both fights at and pays from: the card CR, else the matched SRD block, else `crForFoeLevel`.
   - `crForFoeLevel` is SRD 5.2.1 "XP Budget per Character" at the foe's level: the Low band for a common foe, High for a mini-boss or boss.
   - `statBlockForEncounter`'s engine block reads the same CR. This follows John's needs-john ruling: "an SRD block where one fits, a CR otherwise".
3. The two copies of `encounterKind` (`engineFight.ts`, `sandboxXp.ts`) are merged into one export in `xpRules.ts`. The E.3 CR uses it too.
4. The solo level-1 budget check found no deviation. `encounterXpBudget(1, 1, band)` gives 50 / 75 / 100, the SRD 5.2.1 Low / Moderate / High row. A party scales by its size, and `roundFight.startCombat` caps both the block and the head-count by it. Nothing was changed there.
5. `progression: 'xp'` is kept. The tt5 and tt6b milestone assertions were not failing, so they needed no retirement.

Deletions are logged in `tt-cut-log.md` under "q31-E".
