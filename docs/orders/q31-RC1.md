# q31-RC1: fight outcome read from the engine record (Order RC-1)

Stamp `2026-10-15w` (from `2026-10-15v`). A play change: settled-fight beats commit differently, so it bumps the stamp and deploys `gm-turn`.

## Cause

- `src/game/engineResult.ts:93` (at `022a64b4`) `beatCarriesTerminalFight` matched the writer's prose against kill-word regexes (`WENT_DOWN` :82, `TERMINAL_WORDS` :85-90, `FIGHT_OVER` :79).
- `src/game/beatCommitGate.ts:222` used it as the `outcome` "fact left out". A miss sent a good draft back for a fight rewrite (`writerTurn.runWriterTurnFightOnly`), then appended the engine sentence (:241).
- `src/game/turnCheck.ts:220` used it for `fightTold`.
- The outcome was already engine-decided (`terminalFightOutcome`, from the ENGINE RESULT). Only the "did the prose tell it" test read words, so every new phrasing ("lay quiet") grew the list (tt-fix-14).

## Fix

- **Deleted** `FIGHT_OVER`, `WENT_DOWN`, `TERMINAL_WORDS` and `beatCarriesTerminalFight` (client and edge mirror).
- **`beatCommitGate.fightFactsLeftOut`** no longer has an `outcome` field. The fight rewrite now triggers only on the forced attempt (tabletop) and dropped foe hits. Both are outside this order.
- **`withMissingFightFacts`** always closes a settled-fight beat with the engine's `terminalOutcomeSentence`. It adds the sentence once: not when the beat already holds that exact sentence.
- **`writerTurn.runWriterTurnFightOnly`** applies that on every accepted path (first draft, retried, added). The writer's words are kept as written and are never tested for the outcome.
- **`turnCheck.checkActionFollowed`**: `fightTold` is any non-escape fight the engine settled this turn.
- **Contradiction check:** the existing `completedEventPacket.proseViolatesEventPacket` → `aliveVsDeadContradiction` (dead foe acting, kill words during a live fight) stays the only one. No new checker and no new word list.
