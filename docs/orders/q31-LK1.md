# q31-LK1: locks and alarms (all modes)

Stamp `2026-10-16f` (from `2026-10-16e`). Play change: shared lock/alarm resolve on SkillGate data (key, SK-4 pick, fail time + SK-3 noise, three-fail tool break, spot/disarm). Client path (`lockAttempt` + `useGame` / `dungeonCard`); edge sync for `mapEngine` / `types` / `checkMath` / `dungeonSeed` / `npcLifecycleFsm`.

## Cause

- **LK-1** (`skillGates` / `dungeonSeed` / `checkMath` / `dungeonCard` OPEN): locks were rank gates only (`SkillGate.skill` + `rank`). No lock `dc`/`tier`/`key`/`alarm`/`kind`, no pick fail streak, no tool break, no alarm spot/disarm, no clock cost on fail. Safes used the same medium thievery gate as chests.

## Fix

- Extend `SkillGate` with optional LK-1 fields; `LOCK_KIND_DEFAULTS` + `normalizeLock` fill door/chest/safe/guarded (safe/guarded higher DC + alarm by data).
- One `resolveLockAttempt` (`lockAttempt.ts`): key opens with no roll; pick uses SK-4 / Thieves' Tools; fail advances `advanceClock` and runs `individualStealth` (or sounds an unspotted alarm); three fails remove tools (TT receipt notes GM ruling); Master-grade tools need min Lockpicking level.
- `lootLock` seeds safe/guarded defaults; `checkMath` reads lock dc/tier; `useGame` + `dungeonCard` call the same resolve path.
- ruleCount: deleted dead `combatResolution.ts` + `stripeCheckout.ts`; lifecycle section arrows rewritten as loops.
