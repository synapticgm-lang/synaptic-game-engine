# q31-L1: LitRPG quest steps tick + RC-2 verb lists gone

Stamp `2026-10-16a` (from `2026-10-15z`). Play change: LitRPG quest find/meet and the shared matcher, so the stamp moves. Edge: `intentParser.ts` synced + `gm-turn` deploy (observe/search stems).

## Cause

- `src/game/questTargets.ts:23-24` (`SEARCH_VERB` / `TALK_VERB`) and `:80-81` (`actionTakes`): a step ticked only when the typed line matched those two local lists (or a person target already had a place). LitRPG System / spine wording (`examine`, unlisted find verbs) missed them → 0 quest steps across distill LitRPG laps (L1).
- `src/game/tabletopQuestProgress.ts` `placeTabletopQuestTargets` / find path: gated to `engineMode === 'dnd'` only, so LitRPG never placed targets and never ran `findQuestTargets`.
- `intentParser` observe/search stems used `\bexamin\b` / bare `investig`, so `Examine the altar` / `investigate` parsed as `other`.

## Fix

- **Deleted** `SEARCH_VERB`, `TALK_VERB`, and private `actionTakes` (tt-cut-log § q31-L1).
- **One shared matcher** `actionMatchesObjective(step, action)` in `questTargets.ts`: exact `stepChip` (verb+object), then `parsePlayerIntent` class (`search`|`observe` find; `talk` meet) + named object/target. `findQuestTargets` still requires `targetSpot`. **K, G-m57, QV import this** — no second checker.
- **LitRPG** places targets (`usesTargetTicks`: `dnd` | `litrpg`) and ticks via `findQuestTargets` in `applyTabletopQuestTurn`. **Chips stay tabletop-only** (`playOpen` / `tabletopStepChip` remain `dnd`) so LitRPG talk stages keep `storyChip` (fix-run 1: `questGiverStage` regressed when LitRPG reused the tabletop chip path).
- **intentParser**: search/observe stems accept `investig…` / `examin…` / `observ…`.
