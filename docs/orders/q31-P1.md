# q31-P1: run-pacing flags reject writer turns

Order P-1 from `docs/orders/queued-fix-orders.md` (distill findings). Scripts only. Nothing in game code, prompts or edge copies changed, so gm-turn was not deployed. The stamp moves to `2026-10-15k` because John's session instruction asks for one. The standing brief alone would not bump for a tester-only change. This bump also finishes q31-A's, which moved the HUD and version.json to `15j` but left `runManifest.BUILD_STAMP` and the 24 stamp tests on `15i`.

## Cause

- `scripts/fate-autoplay/autoThumbs.mjs:136-139` (at `3f499a47`) pushed `same place N turns, no progress` and `XP stall N turns` into the per-turn `down` list, which set that turn's `verdict:'down'`.
- `scripts/distillCollect.mjs:88` rejected any turn with `verdict === 'down'`. The pacing of the engine and the autoplay player was therefore counted against the writer. Chip and map flags (`unrelated-chip`, `bad-floor-plan`) were counted against the writer the same way.

## Fix (one shared mechanism)

- **`judgeNotes.mjs`** (the module autoThumbs already shares) now holds the one writer-kind allowlist, `WRITER_FLAG_KINDS`, plus `flagKind(entry)` / `isWriterFlag(entry)`.
  - Included: the judge, stiff-line and ignored-action kinds, the turnCheck prose kinds (`repeated-habit`, `broken-line`, `plays-player`, `wrong-voice`, …), and autoThumbs' own prose kinds (`fallback`, `junk`, `repeated line`, `prose`).
  - Not included: chip, map, quest and engine kinds.
- **`autoThumbs.mjs`:**
  - The two pacing flags go to the run-level `circling.pacing` list (`{turn, flag}`) and to a `Pacing:` line under Circling in report.md. They are never a turn verdict.
  - The JUNK and fight-contradiction flags now carry a kind prefix (`junk:`, `prose:`). Their text is unchanged.
- **`distillCollect.mjs`:** `local down flag` = `th.down.some(isWriterFlag)`. It reads existing thumbs.json files, so distill-1 is re-scored without a judge rerun.
