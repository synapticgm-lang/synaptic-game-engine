# q31-M3: scene exit + leapfrog Previous (Order M part 3, steps 5–6)

Tag `q31-M3`. Stamp `2026-10-16y`. Play change: leaving a place (or a dungeon) condenses the place ledger and leapfrogs Previous; the writer SCENE block shows Current + compact Previous. Never calls `closeDungeon`. Edge `types` / `infoSheet` / synced `semanticLoopDetector` change, so `gm-turn` is redeployed.

## Cause

`src/game/sceneLedger.ts` (M1–M2) stamped a full ledger on the current place and never exited it. `PlaceRecord.sceneLedger` kept `said`/`described` forever. There was no Previous slot (`types.ts` SceneLedger comment: “Current scene only until the exit pass”). Leaving a dungeon still went through `closeDungeon` / `maybeAutoCloseDungeon` for the card, but the scene ledger had no leave path of its own — long scenes and travel forgot pinned promises once HERE moved.

## Fix

**Step 5 + leapfrog (step 6).** `advanceSceneLedger(before, after)` runs at commit (before `stampSceneLedger`) in `useGame.ts` and `fateAutoplay.ts`.

- Boundaries: `placesDiffer` on the HERE label, or `activeDungeon` cleared (dungeon leave). Never calls `closeDungeon`.
- On exit: left place’s ledger is rewritten condensed (pinned promises/threats/clues/asked/present only; `said`/`described` dropped; `arcSummary` one-liner). Returning reopens from that condensed base (`reopening` resets `openedTurn`).
- Old `GameState.scenePrevious` → timeline facts (`kind: 'scene'`) via `mergeTimeline`.
- New Previous = compact pins from the place just left.
- Travel is its own scene: A → road sets Previous = A; road → B folds label to `A + road to B` without dumping Previous yet.
- `formatSceneLedgerBlock` renders Current + Previous (Previous ≤ `PREVIOUS_CHAR_BUDGET` 200 inside `SCENE_CHAR_BUDGET` 600).

Encounter-clear and talk-end boundaries are not wired this pass (NEXT).
